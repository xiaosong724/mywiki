## 一、已定决策（已实现）

### 架构与部署
- 后端 Node.js 零依赖单进程（node:http/sqlite/WebSocket/fetch）→ 不用 Python/Docker；手机部署只需一个 node 二进制。
- 数据单文件 SQLite（`server/data/knowledge.db`）→ 备份=复制文件，交接=拷 data/。
- 双入口：网页管理（8000 端口）+ QQ 机器人（NapCat/OneBot11 WS）。
- **2026-08-16**：手机端只跑 wiki + NapCat；DSH 只在电脑本地跑（127.0.0.1:3080），手机端已删干净。开发流程：电脑本地测试 → 用户确认 → git push → 手机 git pull。
- **2026-08-16**：NapCat（QQ 机器人）只在手机上运行和登录，电脑端不再跑机器人 → 只需登录一个 QQ（手机 NapCat 那个）；wiki 本体仍电脑开发、确认后 git 同步到手机。
- 微信暂不接入（Gewechat 停止维护）。

### 权限模型（详见 权限管理设计方案.md）
- 群组权限：按群限制可用类型；关闭/自由/前缀三种触发；群成员私聊权限；成员默认权限（group_configs 表）。
- 成员权限：按 QQ+群+分类 配置 查/增/改/删（member_permissions 表）。
- **群主不豁免**：群主也严格按成员权限执行（用户明确确认，保持此语义）。
- **关闭的分类 = 完全隐形**：搜索/详情返回"没找到"，不泄露存在性。
- 前端权限保存键必须是英文 read/create/update/delete（曾用中文键导致保存无效，已修）。
- 管理操作（/分类名、AI rename_type）仅管理员：config.bot.adminQqIds，为空回退 notify.qqUserId。
- 删除确认必须回到发起删除时的同群/同场景。
- 群主在"成员私聊权限"里始终豁免。
- 密码明文存本地，用户明确暂不加密。

### 类型与条目
- 类型合并：删除 important_date（重要日期）→ 并入 note（备忘提示 📌）；note 支持 date/time/advance_days/repeat_yearly，提醒精确到分钟。
- 相对时间提醒：`一分钟后`/`半小时后`/`2小时后` = 当前时间 + 偏移（parseRelativeTime）。
- **备忘内容存用户原话**：content 原封不动保存用户发的句子（规则 22 + 工具兜底）。
- 备忘提醒发到**创建时的群**并 [CQ:at] @创建者（entries.source_group），不私发；私发兜底。
- 分类显示名可改（type_label_overrides 表 / `/分类名` 命令）。

### AI 链路
- AI 变更统一两位确认码（pendingOps，10 分钟 TTL），回复确认码才执行。
- AI 负责**重复判断 + 多版本回答**：知识库已有内容时，玩家问是否可告知"有多种，分别是谁提供的"（getByTitle 模糊匹配 + 空壳条目转"确认修改"）。
- AI 搜不到时不编造，返回"没找到"（隐形规则 17）。
- AI 调用后私聊费用报告 + /user/balance 钱包。
- AI 搜索自动剥离类型词（"备忘提示"等当关键词导致搜不到，已修）。
- **2026-08-16**：搜索结果排序改为**标题匹配优先**（标题命中关键词的词越多越靠前，同级按 updated_at 倒序），避免精确命中条目被"updated_at 倒序 + limit 截断"挤出（搜「五行丹」曾因排在玩家指南后面被 AI 搜索 limit=6 截断而返回"没找到"，已修；AI 搜索 limit 提到 10）。

### 机器人适配
- OneBot11 WS 适配器（bot/onebot.mjs），换机器人 = 换 kind/配置，唯一实现点。
- 重启 QQ/NapCat：网页设置页有二维码显示 + 刷新 + 重启按钮（config.bot.restartCommand）。
- 二维码路径 config.bot.qrcodePath（默认 NapCat.Shell/cache/qrcode.png）。
- **设定修改不能私聊（2026-08-16）**：权限/配置/改名等设定类修改只能在群里带前缀执行，私聊机器人拒绝设定修改 → 避免绕过群权限、保证操作在群里可追溯。

### 全量知识库（文件型知识域存储，2026-08-16 定）
- **需求**：修仙模组这类大而稳定的知识域拆成 221 条 SQLite 条目后，AI 搜索有截断/漏检风险（「五行丹」事件），且维护碎片化 → **决策：改用 md 文件存储，该类不再用 SQLite 条目**（条目保留作历史不删，md 为权威源）→ 原因：全量注入零漏检 + DeepSeek 前缀缓存命中 + 网页/QQ 双端可管理。
- **双文件结构**：主 md（`server/data/knowledge/<type>/main.md`，用户用 AI 整体更新或网页上传，低频改动）+ 动态 md（同目录 `dynamic.md`，QQ 带前缀指令记录 + 网页可编辑，高频小增量）；查询时拼接注入 system 固定前缀（**主在前、动态在后**）→ 主 md 稳定缓存几乎全命中，动态追加只裂末尾少量缓存（命中 0.02 元/百万 vs 全价 1 元/百万）。
- **触发条件 = 必须带前缀指令**（复用群配置 prefix 模式，如 `wiki3`）：带前缀的消息才加载全文，普通自然发言（free 类型）不注入 → 零负担、按前缀缓存命中。
- **全量知识库类型强制指令触发（2026-08-16）**：配置了 `knowledge.mainFile` 的类型，群触发规则只能是「前缀触发」或「关闭」，**不允许自由触发**（保存时后端强制转 prefix，缺省前缀 `wiki`）。
- **未配置权限的群不能用机器人（2026-08-16）**：群不在 group_configs 或已停用 → 机器人完全不响应（群消息一律忽略），不再按"全部类型可用"放行；私聊不受影响。
- **主 md 版本管理**：网页上传更新 → 旧版自动保留（`versions/vN.md` 最多 5 个最新），可一键回滚（回滚前当前内容自动存档）；**切换前先弹窗预览**该版本内容再确认。
- **AI 写动态 md**：新增内容用 append_knowledge（追加到末尾，缓存友好），仅更新既有内容才 edit_knowledge（中间编辑），沿用两位确认码；**主 md 只能网页上传/用户整体更新，QQ 不改主 md**。
- **主 md 布局原则**：频繁改动的内容（常见问题、更新公告）集中放文件末尾（常见问题在更新公告上面），改动少的表格图鉴放中间 → 改动只裂末尾缓存，前缀命中区最大化。
- 数据迁移：221 条修仙条目按类别导出为「§22 物品图鉴」表格并入主 md（`scripts/export-mod-kb.mjs`，6 丹药/15 药材/18 矿石/80 妖丹/15 妖兽/8 灵宠/15 五行能力/12 指令/7 更新公告；主 md ≈47.5KB ≈1.5万 tokens）。

## 二、NapCat 手机部署结论（2026-08-16 晚研究清楚）

- NapCat v4 在 Linux 必须**寄生在官方 QQ 客户端进程内**：napcat.cjs 钩 process.dlopen，等 QQ 加载 wrapper.node 时拿 session/loginService 再调 NCoreInitFramework。直接 `node napcat.mjs` 会静默退出（库不是入口）。
- 注入方式：`LD_PRELOAD=/lib/arm64/libnapiloader.so` + `NAPCAT_EXTERNAL_SCRIPT_PATH=/opt/napcat/nativeLoader.cjs`，启动 `qq --no-sandbox`（参考官方 NapNeko/NapCat.Docker.Framework，支持 arm64）。
- QQ 是图形程序 → 容器内需 Xvfb 虚拟显示。
- QQ Linux arm64 包：`linuxqq_3.2.30-50969_arm64.deb`（qqdl.gtimg.cn，202MB）；NapCat 4.18.19 与之匹配（官方 CI 同版本组合）。
- 登录后二维码存 `/opt/napcat/cache/qrcode.png`（NapCatPathWrapper 默认写 napcat 目录）。
- 手机 NapCat 部署进度与卡点：见 `docs/03_运维_手机.md`。
- 大文件或下载源网速慢时 → 用户提供下载地址并自行下载好，AI 再把文件从电脑传到手机（2026-08-16）。
- 手机容器 apt 必须加 `APT::Sandbox::User "root"`（Android 限制非 root UID 建 socket，apt 默认以 _apt 跑会报 socket Permission denied；已持久化到 /etc/apt/apt.conf.d/90android-sandbox）（2026-08-16）。
