# docs/04 · Skill 使用手册（忘了就打开这份）

> 这套 skill 让"开新会话 / 记决策 / 收尾"一句话搞定，不用背模板。
> 使用前提：工作目录在 `C:\my-wiki`（项目根），DSH 运行中。
> 更新日期：2026-08-16

## 一、总共 4 个 skill 一览

| Skill | 什么时候用 | 怎么触发 | 它自动做什么 |
|---|---|---|---|
| `wiki-dev` | 开「wiki 功能开发」新会话 | 说 `wiki开发新会话` 或输 `/wiki-dev` | 读 `docs/00` `01` `02`，报告当前进度与待办，确认理解后等你下任务 |
| `phone-ops` | 开「手机运维 / NapCat」新会话 | 说 `手机运维新会话` 或输 `/phone-ops` | 读 `docs/00` `03`，报告手机服务状态、NapCat 卡点与下一步 |
| `record-decision` | 讨论出结论了，要记下来 | 说 `记下这个决策：...` 或输 `/record-decision` | 把结论按"一行一条"追加进 `docs/01_需求与决策.md`，跨会话复用 |
| `wrap-up` | 要结束/换会话前 | 说 `收尾` 或输 `/wrap-up` | 回顾本会话 → 更新 `01` 决策、`02` 看板、`03` 运维（如涉及）→ git 提交推送 → 提示下一步开哪个会话 |

## 二、日常完整流程（照着做就行）

```
① 开新会话      → 说「wiki开发新会话」或「手机运维新会话」
② 干活          → 正常聊，让 AI 做事
③ 出结论了      → 说「记下这个决策：<结论>」
④ 干完/要换会话 → 说「收尾」
⑤ 开下一个会话  → 重复 ①（收尾时会告诉你该开哪个）
```

## 三、两种触发方式（任选）

1. **自然语言**（推荐）：`wiki开发新会话`、`记下这个决策：群主不豁免`、`收尾`
2. **斜杠命令**（更确定）：`/wiki-dev`、`/phone-ops`、`/record-decision`、`/wrap-up`

两者效果一样；记不住名字时用自然语言就行，AI 会根据描述自动匹配。

## 四、Skill 文件在哪、怎么改

所有 skill 都在项目的 `.dsh/skills/` 目录下，一个文件夹一个 skill：

```
.dsh/skills/
├── wiki-dev/SKILL.md          # 开 wiki 开发会话的初始化逻辑
├── phone-ops/SKILL.md         # 开手机运维会话的初始化逻辑
├── record-decision/SKILL.md   # 记决策的落盘逻辑
└── wrap-up/SKILL.md           # 收尾归档逻辑
```

- 想改"初始化读哪些文档""收尾要不要自动推送 git"等行为 → 直接改对应 `SKILL.md`
- 改完**立即生效**（DSH 实时监听），无需重启
- 文件跟着 git 走，手机端也能同步同一份

## 五、配套文档（docs/ 是什么）

| 文档 | 内容 |
|---|---|
| `docs/00_总入口.md` | 项目地图：会话分工、skill 用法表、文档索引、铁律 |
| `docs/01_需求与决策.md` | 决策日志：所有已定决策一行一条（skill 读写这个） |
| `docs/02_待办与进度.md` | 任务看板：状态 \| 卡点 \| 下一步 |
| `docs/03_运维_手机.md` | 手机服务器 + NapCat 部署（自包含） |
| `docs/04_skill使用手册.md` | **本文件**：skill 怎么用 |

> 记不住 docs 编号没关系：每个新会话 AI 都会先读 `docs/00` 这张地图，它会告诉你该看什么。
