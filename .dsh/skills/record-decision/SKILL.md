# 记录决策 / 需求

## 作用

把讨论出的**最终结论**落盘到 `docs/01_需求与决策.md`，一行一条，供所有后续会话复用——这是省 token 的核心动作。

## 流程

1. 如果用户没有在话里给出完整内容，先向用户确认要记什么（一句话复述）。
2. 读 `docs/01_需求与决策.md` 找到合适的章节（已定决策 / NapCat 部署结论 / 待定暂缓），新内容**追加到对应小节末尾**，格式：

   ```
   - 需求/问题 → 最终决策 → 原因（日期 YYYY-MM-DD）
   ```

3. 如果内容不属于现有小节，新建小节（如"## 四、..."）再追加。
4. 写完后回一句：已写入 `docs/01_需求与决策.md`（第 X 节），确认无误。

## 注意

- 只记**结论**，不记讨论过程、备选方案细节。
- 一行放不下就两行，但保持"一条决策一条"的粒度。
- 不确定该不该记 → 记（多记无害，省的是以后的重复推理）。
